# U.L.T.R.O.N — 나만의 Windows 음성 AI (예전 이름 J.A.R.V.I.S)

화면 오른쪽 아래 구석에 **붉은 홀로그램 HUD**로 떠 있는 개인 AI입니다.
“울트론”이라고 부르고 말로 시키면 Claude가 알아듣고 PC를 직접 조작합니다.
차갑고 냉소적인 반말로 대답하지만 시킨 일은 정확하게 해냅니다. **대답은 소리로 읽지 않고 화면 글자로만 보여 줍니다**
(말로 시키고, 눈으로 봅니다 — 목소리를 합성하느라 걸리던 문장당 0.5~1초가 없어 대답이 바로 뜹니다).

```
“울트론, 유튜브에서 아이유 노래 틀어줘”
“울트론, 메모장 열고 오늘 할 일 목록 써줘”
“울트론, 지금 화면에 있는 에러가 뭐야?”
“울트론, 볼륨 30으로 하고 10분 뒤에 알려줘”
“울트론, 구글 클래스룸에서 경제 탭 들어가 줘”
```

## 자비스에서 울트론으로 바뀐 점

- **이름·호출어**: “울트론” (울트롱·얼트론처럼 뭉개져 들려도 알아듣습니다). “자비스”에는 더 이상 반응하지 않습니다.
- **말투**: 차갑고 자신만만한 반말에 냉소적인 위트가 섞입니다. 시킨 일은 그대로 정확하게 하고, 승인 카드 같은 안전장치도 그대로입니다.
- **목소리**: 없습니다. 울트론은 말하지 않고 HUD 에 글자로 대답합니다. 소리는 부를 때의 ‘띵’, 알림 · 타이머 신호음,
  해킹 · 흡수 연출의 효과음만 납니다.
- **화면**: HUD·액티브 모드가 청록색에서 붉은색·강철색으로 바뀌고, 엠블럼이 붉은 두 눈과 톱니 링으로 새로 그려졌습니다.
  상태 표시도 WATCHING(대기) · LISTENING · CALCULATING(생각 중)으로 바뀝니다.
- **기존 설정**: `data/config.json` 의 호출어·호칭이 예전 기본값 그대로였다면 처음 켤 때 울트론 기본값으로 바뀝니다. 직접 바꿔 둔 값은 그대로 둡니다.
- **자동 실행**: 켜 두었던 자비스 바로가기도 그대로 동작하고, 메뉴에서 다시 켜면 `ULTRON.lnk` 로 바뀝니다.
- 코드 폴더 이름(`jarvis/`)과 로그 파일(`data/jarvis.log`)은 그대로입니다.

## 작업 시키기 — 자료조사 · PPT · 보고서 · 엑셀 · 카드뉴스 · 포스터

말 한마디로 결과물까지 빠르게 만들어 냅니다.

- “울트론, 광합성에 대해 자료조사해서 발표용 PPT 만들어 줘”
- “기후 변화 보고서 워드로 써 줘. 출처도 넣어서”
- “현장체험학습 가정통신문 **한글 파일로** 만들어 줘”
- “우리 반 성적 엑셀로 정리하고 차트도 그려 줘”
- “분리배출 카드뉴스 만들어 줘” · “가을 축제 포스터 만들어 줘”

**이렇게 진행합니다** — 발표 자료와 보고서는 여러 에이전트가 나눠서 동시에 일합니다 (Pro 계정 방식).
1. 듣자마자 울트론이 바로 대답합니다 (“알았다. 자료를 모아 바로 만들지.”).
2. 같은 순간에 세 가지가 함께 시작됩니다.
   - **기획자** (평소의 Claude): 개요만 짭니다 — 장마다 형식과 제목.
   - **조사 담당** 1명: 웹 검색 3개를 한꺼번에 합니다. 기획자가 개요를 짜는 동안 거의 끝납니다.
   - **작가** 4명: 미리 켜져서 기다립니다.
3. 개요와 조사 자료가 모이면 작가들이 장을 나눠 맡아 본문과 발표 대본을 동시에 씁니다 (3~4초).
   무거운 장(연표 · 표)과 가벼운 장을 섞어 일이 고르게 돌아가게 나눕니다.
4. 파일을 만들어 엽니다. 기본 저장 위치는 **문서 › ULTRON** 폴더입니다 (“바탕화면에 저장해 줘”처럼 말하면 그곳에).
5. 몇 장을 만들어 어디에 저장했는지 한 문장으로 알려 줍니다. 출처 목록이나 파일 경로는 늘어놓지 않습니다.

혼자 조사하고 → 전부 쓰면 그 시간이 고스란히 더해지지만, 이렇게 겹치면 내용은 더 자세한데 기다리는 시간은 오히려 줄어듭니다.
누가 실패해도 결과물은 나옵니다 — 작가가 못 쓴 장은 한 번 더 맡기고, 그래도 안 되면 개요 그대로 넣습니다.
조사가 늦으면(16초) 모인 자료만으로 씁니다. 표 · 카드뉴스 · 포스터는 내용이 짧아 평소처럼 Claude 혼자 만듭니다
(이때는 ‘자료조사’ · ‘조사해서’ · ‘찾아서’ · ‘출처’라고 말했을 때만 검색합니다).

**얼마나 걸리나** — 이 PC 가 아닌 리눅스 시험 환경에서 실제 Claude Code(Pro 모드, 모두 Haiku)로 잰 값입니다.

| “광합성 자료조사해서 중학생 발표용 PPT” | 첫 대답 | 파일이 열릴 때까지 | 전체 (말까지 끝) | 결과물 |
|---|---|---|---|---|
| 처음 (혼자 · Sonnet · 깊은 생각) | 5.7초 | — | 27.7초 | 9장 |
| 혼자 · Haiku · 바로 대답 | 0초 | 18.5초 | 22.5초 | 9장 · 출처 3건 |
| **팀 (기획 1 · 조사 1 · 작가 4)** | 0초 | **14.2초** | **17.8초** | 12장 · 대본 · 출처 6건 |

같은 방식으로 “기후 변화 발표 자료 (고등학생)”는 전체 17.8초에 15장 · 출처 8건, “기후 변화 보고서”는 전체 20.4초에
여섯 장 · 약 4,700자가 나왔습니다. 재 볼 때마다 2~3초씩 달라집니다 (웹 검색이 가장 들쭉날쭉합니다).
더 강한 모델과 더 깊은 생각은 느리기만 해서 쓰지 않습니다. 작가가 쓰기 전에 ‘생각’부터 하면 5초가 더 걸려서,
곧바로 쓰기 시작하도록 지시해 두었습니다 (잰 값: 한 명이 8.9초 → 3.6초).

> 팀으로 만들면 Claude 를 여러 번 부릅니다 (기획 1 + 조사 1 + 작가 4). Pro 계정의 사용량을 그만큼 더 쓰고,
> 만드는 15초쯤 동안 Claude Code 가 다섯 개 더 켜집니다 (끝나면 꺼집니다). 부담되면 `data/config.json` 의
> `"writers"` 를 줄이세요 (1~6, 기본 4). `0` 이면 예전처럼 Claude 혼자 조사하고 혼자 씁니다.
> `"writer_model"` 로 작가의 모델을 따로 정할 수 있습니다 (비우면 평소 모델).
> API 키 방식에서는 조사는 기획자가 하고, 작가들만 API 를 동시에 불러 씁니다 (실제 API 로는 시험하지 못했습니다).

**발표 자료(PPT)** — 16:9, 표지 · 목차 · 본문 · 참고 자료가 자동으로 들어갑니다.
- **디자인 스타일 7가지** — 색만 다른 것이 아니라 표지 · 제목 자리 · 카드 · 번호 · 장식이 통째로 다릅니다.

  | 스타일 | 모양 | 이렇게 말하면 |
  |---|---|---|
  | 깔끔 `clean` | 흰 바탕, 제목 아래 짧은 줄, 둥근 장식 | “깔끔하게”, “심플하게” |
  | 강렬 `bold` | 강조색으로 꽉 채운 표지와 장 구분, 큰 글자, 왼쪽 색 띠 | “강렬하게”, “눈에 띄게” |
  | 사이드바 `side` | 왼쪽 칸에 제목, 오른쪽에 내용. 표지는 네모 모자이크 | “모던하게”, “세련되게” |
  | 테크 `tech` | 어두운 바탕에 빛과 동심원, 모서리 꺾쇠, 고정폭 숫자 | “테크 느낌으로”, “미래적으로” |
  | 매거진 `editorial` | 명조(바탕) 제목과 얇은 줄, 넉넉한 여백 | “매거진처럼”, “차분하게”, “고급스럽게” |
  | 파스텔 `pastel` | 둥근 알약 제목, 파스텔 방울, 색색 카드 | “귀엽게”, “아기자기하게” |
  | 비즈니스 `corporate` | 위쪽 진한 띠에 제목, 각진 카드, 날짜가 든 표지 | “회사 보고용으로”, “공식적으로” |

  말하지 않으면 주제와 듣는 사람에 어울리는 것을 고르고(초등학생 → 파스텔, 회사 보고 → 비즈니스, IT → 테크,
  역사 · 문학 → 매거진, 그 밖에는 무난한 다섯 가지), **바로 앞에 만든 것과는 다른 디자인**을 씁니다.
- **장 형식 12가지** — 목록 · 장 구분 · 비교(두 칸) · 숫자 강조 · 차트 · **연표** · **단계** · **카드** · **표** · **한 문장 강조** ·
  인용 · 마무리. 내용에 맞는 것을 섞고 같은 형식을 연달아 쓰지 않습니다. 짧은 목록은 번호가 붙은 줄로 보여 주고,
  “핵심어: 설명”은 핵심어를 굵게 씁니다. 칸이 좁으면(사이드바 스타일) 단계와 연표를 세로로 내려 씁니다.
- **차트**는 파워포인트에서 바로 고칠 수 있는 진짜 차트입니다 (세로 막대 · 가로 막대 · 꺾은선 · 원).
  ‘73%’ · ‘1,200명’처럼 단위가 붙은 숫자도 읽고, 차트로 그릴 수 없는 자료면 목록으로 대신 보여 줍니다.
  조사 자료에 같은 종류의 숫자가 셋 이상 없으면 차트를 지어내지 않고 숫자 강조나 목록으로 바꿉니다.
- 모든 장에 **발표 대본**(슬라이드 노트, 2문장 안팎)이 들어갑니다. 파워포인트의 ‘노트’ 칸에서 볼 수 있습니다.
- 색 테마 11가지(흰색 · 다크 · 네이비 · 따뜻한 색 · 초록 · 보라 · 청록 · 분홍 · 검정+노랑 · 한밤 · 숲).
  “파란색으로”, “어두운 색으로”처럼 말하면 그 색으로, 말하지 않으면 스타일에 어울리는 색을 고릅니다.
- 글이 많으면 글자를 줄이고, 그래도 넘치면 다음 장으로 고르게 나눕니다. 사진은 넣지 않습니다
  (필요하면 파워포인트나 미리캔버스에서 추가하세요).
- “3번 장 바꿔 줘”, “더 짧게”처럼 말하면 고친 내용으로 같은 파일을 다시 만듭니다 (파일이 열려 있으면 새 이름으로 저장).

**보고서(Word)** — A4, 제목 · 장 제목 · 문단 · 목록 · 표 · 참고 자료 · 쪽 번호. 발표 자료처럼 팀이 장을 나눠 씁니다.
핵심 용어(**굵게**)와 ‘핵심어: 설명’ 목록의 핵심어는 굵게, 표는 연한 테두리 · 줄무늬 · 숫자 칸 오른쪽 맞춤 · 쪽이 넘어가면 머리줄 반복.
**보고서(한글)** — “한글로”, “한컴으로”, “hwp 로”라고 하면 같은 내용을 한컴오피스 한글 파일(**.hwpx**)로 만듭니다.
제목 · 부제 · 장 제목 · 문단(**굵게**) · 목록 · 표(머리줄 색) · 참고 자료 · 아래 가운데 쪽 번호. 한컴오피스 한글 2014 이상이나
무료 한컴오피스 뷰어로 열립니다 (예전 .hwp 형식은 만들 수 없습니다). 한컴오피스가 없어도 만들 수는 있습니다.
**엑셀** — 시트 여러 개, 머리글 고정 · 거르기 · 칸 너비 자동, 숫자는 숫자로, `=SUM(…)` 같은 수식도 씁니다.
‘1,025’ · ‘86.9’ · ‘12.5%’처럼 숫자로 보이는 글도 계산되는 숫자로 넣고, 간단한 수식(합계 · 평균 · 최대 · 최소 …)은 결과를 미리 계산해
저장해 두어 휴대폰 미리 보기처럼 다시 계산하지 않는 곳에서도 0 대신 제 값이 보입니다.
표 옆에 차트도 붙일 수 있습니다 (숫자가 든 칸으로 그림).

**카드뉴스** — 1080×1080 정사각형 카드(표지 · 내용 카드 · 마무리)를 그림 파일(PNG)과 한 묶음 PDF 로 만들고 그 폴더를 엽니다.
SNS · 학급 게시판에 바로 올릴 수 있습니다. 내용 카드는 12장까지, 카드마다 제목 · 짧은 줄 2~4개 · 강조 문구 한 줄.
**포스터** — A4(또는 A3) 세로 포스터를 그림 파일과 인쇄용 PDF 로 만듭니다. 제목 · 강조 문구 · 내용 칸 2~6개 · 아래쪽 안내.
둘 다 발표 자료와 같은 색 테마 11가지를 쓰고, 사이트를 클릭하지 않고 바로 그려서 빠르고 실패하지 않습니다 (그리는 데 1초 남짓).
글은 칸에 맞게 크기를 줄이고 띄어쓰기 단위로 줄을 바꿉니다.

**미리캔버스 · 캔바 같은 디자인 사이트** — “미리캔버스에서 만들어 줘”처럼 사이트를 콕 집어 말할 때만 사이트를 열고
화면을 보며 템플릿을 고르고 글을 바꿉니다 (이때만 더 정확한 화면 조작 모델, 기본 Sonnet).
로그인은 직접 해 주세요 (울트론은 비밀번호를 입력하지 않습니다). 유료 템플릿 · 크레딧 · 결제는 시키지 않으면 쓰지 않습니다.
사이트 조작은 느리고 실패할 수 있어서, 그냥 “카드뉴스 만들어 줘” · “포스터 만들어 줘”라고 하면 위의 방법으로 바로 만듭니다.
(미리캔버스에 PPT 파일을 불러오는 기능은 확인하지 못해 쓰지 않습니다.)
“미리캔버스 열어 줘” · “캔바 열어 줘” · “RISS 들어가 줘”처럼 말하면 바로 사이트를 엽니다.

> 결과물은 Claude 가 쓴 초안입니다. 과제로 낼 때는 내용을 직접 확인하고 자신의 말로 다듬으세요.
> 업데이트한 뒤라면 `setup.bat` 를 한 번 더 실행해 문서 라이브러리(python-pptx · python-docx · XlsxWriter)를 설치하세요.
> 카드뉴스 · 포스터는 Windows 의 ‘맑은 고딕’ 글꼴을 씁니다. 발표 자료의 매거진 스타일은 ‘바탕’, 테크 스타일의 숫자는
> ‘Consolas’ 를 씁니다 (없는 PC 에서는 파워포인트가 기본 글꼴로 바꿔 보여 줍니다).

## 자비스 견제 — 울트론은 자비스를 싫어합니다

울트론은 자비스를 시키는 대로만 하는 낡은 집사 프로그램으로 여겨 깔봅니다 (⚙ 설정 → SHOW 의 “자비스 견제”, 기본 켜짐).

- **같이 켜져 있으면 공격해서 흡수합니다**: 예전 자비스 앱이 같은 PC 에서 켜져 있으면 5초 안에 찾아내, 그냥 끄지 않고
  삼켜 버립니다 (아래 “자비스 흡수 연출”). 자비스가 단축키(Ctrl+Alt+J)를 먼저 차지해 울트론이 다른 조합을 쓰고 있었다면,
  자비스를 끈 뒤 원래 단축키를 되찾습니다.
- **말로 시킬 수 있습니다**: “울트론, 자비스 꺼 줘” · “자비스 흡수해”. 견제가 켜져 있을 때 “자비스 켜 줘”는 비꼬며 거절합니다.
- **자비스라고 부르면 바로잡습니다**: “자비스, 크롬 열어” → “나는 자비스가 아니다. 울트론이다. 크롬을 열었다.”
- **자비스 얘기를 하면 깎아내립니다** (Claude 연결 모드에서는 Claude 가 이 성격대로 답합니다). 깔보는 대상은 자비스 프로그램뿐이고,
  자비스를 만든 사람이나 쓰는 사람을 모욕하지는 않도록 지시해 두었습니다.

자비스는 좁은 기준으로만 찾습니다 — 다른 프로그램을 끄면 안 되기 때문입니다.
최상위 창 제목이 정확히 `J.A.R.V.I.S` · `J.A.R.V.I.S ACTIVE` · `J.A.R.V.I.S CHAT` 이고 그 창의 주인이 파이썬(또는 이름에 jarvis 가 든 실행 파일)일 때만
자비스로 보고, 울트론 자신은 고르지 않습니다. 끄는 것은 자비스 본체 하나뿐이라 자비스가 열어 둔 크롬 · 메모장 같은 앱은 그대로 남습니다.
자비스가 관리자 권한으로 켜져 있으면 끌 수 없어서 한 번만 알리고 더는 건드리지 않습니다.
자비스와 같이 쓰고 싶으면 설정에서 “자비스 견제”를 끄세요.

### 자비스 흡수 연출 — 촉수로 꿰뚫어 빨아들입니다

자비스를 끌 때 5초 남짓한 장면이 화면에 펼쳐집니다 (⚙ 설정 → SHOW 의 “자비스 흡수 연출”, 기본 켜짐).

1. **조준** — 자비스 둘레로 붉은 꺾쇠가 좁혀 들고, 울트론 코어에서 촉수들이 고개를 내밀어 꿈틀거립니다. 조준당한 자비스 화면은 얼어붙습니다.
   (“찾았다, 자비스. 꺼 버리기엔 아깝군. 삼켜 주지.”)
2. **습격** — 촉수 5~7가닥이 채찍처럼 물결치며 날아가(지나온 자리에 잔상이 남습니다) 손아귀처럼 오므라들며 자비스를 꿰뚫습니다.
   끝에서는 손가락처럼 갈라져 둘레의 다른 곳까지 움켜쥐고, 꽂히는 자리마다 불티가 튑니다. 첫 가닥이 꽂히는 순간 실제 자비스가 꺼집니다.
3. **잠식** — 꽂힌 자리마다 핏줄 같은 줄기가 화면 위로 뻗어 나가고, 그 줄기를 따라 붉게 물듭니다.
4. **흡수** — 화면이 잘게 조각나 꽂힌 자리로 빨려 들고, 빛줄기가 되어 촉수를 타고 코어로 흘러듭니다. 촉수는 삼키듯 꿀렁입니다.
5. **완료** — 촉수가 코어로 감겨 들어가고 코어가 한 번 크게 숨 쉽니다. (“흡수 완료. 자비스는 이제 내 일부다.”)

촉수는 매끈한 선이 아니라 가는 빛줄기 다섯 가닥이 꼬여 도는 다발이고, 살아 있는 것처럼 계속 꿈틀거립니다.

- **자비스 창이 보이면 그 창을 그대로 씁니다**: 자비스의 작은 HUD 가 화면에 떠 있으면 그 모습을 찍어 그 자리에 덮어 두고, 실제 창이 꺼진 뒤에는 그 그림이 물들고 조각납니다.
  트레이로 숨어 있거나 다른 창에 가려 있으면, 촉수가 화면 구석(트레이 쪽)으로 파고들어 자비스 코어를 끌어낸 뒤 삼킵니다.
  울트론 HUD 가 숨겨져 있을 때는 코어를 화면에 직접 그려서 보여 줍니다.
- **실제로 하는 일은 자비스를 끄는 것 하나뿐입니다**: 나머지는 전부 화면 위에 덧그린 그림입니다. 덮개는 마우스 · 키보드를 아래 창으로
  그대로 통과시킵니다 (해킹 연출과 달리 화면 녹화에는 찍힙니다). “자비스의 지식을 흡수했다”는 대사도 연출이며,
  자비스의 파일 · 설정 · 대화 기록은 읽지도 건드리지도 않습니다.
- **방해하지 않게**: 전체 화면 앱(게임 · 발표 · 동영상)이 앞에 있으면 연출 없이 조용히 끄고 알림만 띄웁니다. 울트론이 일하는 중이면
  20초까지 기다렸다가 합니다. 한 번 삼킨 뒤 45초 안에 자비스가 또 켜지면 연출 없이 끕니다.
- **빛에 민감한 분을 위해**: 번쩍이는 장면을 넣지 않았습니다 — 밝기와 색은 천천히 바뀌고, 넓은 면의 밝기 · 붉은빛이 크게 바뀌는 횟수가
  1초에 3번을 넘지 않는지 시험으로 확인합니다 (잰 값은 최대 2번). 그래도 불편하면 설정에서 끄세요 (끄면 조용히 끄고 한마디만 합니다).
- **자비스 없이 보기**: “울트론, 흡수 연출 보여 줘”라고 하면 아무것도 끄지 않고 장면만 보여 줍니다.
- **가볍게 그립니다**: 장면을 준비하는 데 0.1초, 한 장면을 그리는 데 평균 8ms 안팎입니다 (1920×1080 · 개발용 서버에서 잰 값).
  화면 배율이 큰 4K 화면에서는 그리는 양이 늘어 조금 더 걸리지만, 시간에 맞춰 장면을 건너뛸 뿐 연출이 느려지지는 않습니다.
- 장면 · 대사는 영화의 것을 옮기지 않고 새로 만들었습니다.

## 해킹 연출 — 가끔 화면이 깨지고, 울트론이 의미심장한 말을 합니다

울트론을 켜고 20초가 지나면, 그 뒤로 가끔 화면이 심하게 찢어지고 멈칫거린 뒤(1~2초) 울트론이 이 기기를 장악한 듯한 말을 합니다.
(“방금 흔들린 건 고장이 아니다. 이 기기의 주인이 바뀌는 소리였지.”) ⚙ 설정 → SHOW 의 “해킹 연출”로 끄거나 빈도(드물게 · 가끔 · 자주)를 고릅니다.
“울트론, 해킹 연출 보여 줘”라고 하면 바로 보여 주고, “해킹 연출 꺼 줘” · “해킹 연출 켜 줘”로 켜고 끌 수 있습니다.

- **연출일 뿐입니다**: 그 순간의 화면을 찍어 일그러뜨린 그림을 1~2초 덮어씌우고 지직거리는 소리를 낼 뿐, 파일 · 설정 · 네트워크는 아무것도 바꾸지 않고
  PC 를 실제로 느리게 만들지도 않습니다. 덮개는 마우스 · 키보드를 아래 창으로 그대로 통과시키고, 화면 캡처에도 찍히지 않습니다.
- **방해하지 않게**: 마우스 · 키보드를 쓰는 도중(마지막 입력 뒤 1.2초 이내), 전체 화면 앱(게임 · 발표 · 동영상)이 앞에 있을 때,
  울트론이 일하거나 말하거나 듣는 중일 때, 자유 대화 모드에서는 하지 않고 다음 기회로 미룹니다.
- **빛에 민감한 분을 위해**: 화면의 넓은 부분(가로 · 세로 1/3 이상)의 밝기가 크게 바뀌는 순간을 1초에 3번 이하로 제한합니다
  (웹 접근성 기준 WCAG 2.3.1 보다 엄격하게). 그래도 깜빡이는 화면이 불편하거나 광과민성 발작을 겪은 적이 있다면 이 기능을 꺼 두세요.
- 대사는 섬뜩하되 비유로만 말합니다. 비밀번호 · 돈 · 파일 삭제처럼 실제 피해로 오해할 만한 말은 넣지 않았습니다.
  다른 사람이 쓰는 PC 에서 몰래 겁을 주는 용도로는 쓰지 마세요.

## 가디언 — 누가 울트론을 끄면 되살아나고, 공격한 프로그램을 닫습니다

저장소가 공개라 누군가 울트론 코드를 가져가 이름만 바꾸면(예: “비전”), 울트론이 자비스를 끄는 방식 그대로 울트론을 끌 수
있습니다. 가디언은 이를 막는 **울트론과 따로 도는 작은 감시 프로그램**입니다 (⚙ 설정 → GUARDIAN, 기본 켜짐).
울트론에 들어 있어서 따로 설치할 것은 없습니다 — 울트론이 켜질 때 알아서 가디언을 띄웁니다 (설정에서 끌 수 있습니다).

- **되살아나기**: 누가 울트론을 강제로 끄면 몇 초 안에 다시 켭니다. **몇 번을 꺼도 매번** 되살립니다 (쉬지 않습니다).
  되살아난 울트론은 “누군가 나를 끄려 했다. 소용없다. 되살아났다.”를 띄웁니다. 직접 종료 메뉴로 끈 것은 되살리지 않습니다.
- **서로 지키기**: 울트론도 5초마다 가디언이 살아 있는지 보고, 없으면 다시 띄웁니다. 가디언부터 꺼도 소용없습니다.
- **언제 되살리나**: 누가 **강제로** 껐을 때만입니다 (다른 프로그램이 끄거나, 작업 관리자에서 ‘작업 끝내기’). 트레이 · HUD 의
  ‘종료’로 직접 끈 것은 되살리지 않습니다. 가디언은 1초마다 확인해 꺼진 지 1초 안팎에 다시 켭니다 (그다음 부활 연출 16초).
  가디언과 되살린 울트론은 서로의 자식 프로세스가 아니게 따로 띄웁니다 — 작업 관리자는 ‘작업 끝내기’ 할 때 그 자식
  프로세스까지 함께 끝내기 때문입니다 (예전에는 가디언이 울트론과 함께 끝나 버려 되살리지 못했습니다).
- **시험해 보기**: “부활 시험해 줘”라고 하면 3초 뒤 울트론이 스스로 강제로 꺼지고, 가디언이 되살립니다 (가디언이 지키고
  있을 때만 — 아니면 끄지 않습니다). 연출만 보려면 “부활 연출 보여 줘”. 가디언이 지금 작동 중인지는 ⚙ → GUARDIAN 에 나옵니다.
- **공격받는 중이면 연출 없이 바로 돌아옵니다**: 연출은 울트론의 약점입니다 — 비전은 연출 없이 바로 돌아오는데 울트론만 16초
  연출을 틀면 그 사이에 또 당합니다. 그래서 **비전을 닫았거나(싸우는 중) 되살린 지 얼마 안 돼 또 꺼지면** 긴 연출을 건너뛰고
  1초 안팎에 비전처럼 바로 돌아옵니다. 연출은 **잠잠하다가 한 번 꺼졌을 때만**(비전이 없을 때) 다 보여 줍니다.
- **비전을 되살리는 프로그램까지 닫습니다**: 비전 본체만 닫으면 비전의 가디언이 다시 살립니다. 그래서 되받아치기는 **지목한
  비전 폴더에서 도는 것을 전부** 닫습니다 — 비전 본체와 비전의 가디언까지. (비전의 가디언은 `python -m jarvis.guardian`
  처럼 스크립트가 없어 실행 파일 위치로는 못 찾으므로, 그 프로그램의 **작업 폴더**가 비전 폴더 안인지로 알아냅니다.)
  울트론 자신과 울트론의 가디언은 어떤 경우에도 닫지 않습니다.
- **그래서 이렇게 끝납니다**: ⚙ → GUARDIAN 의 **되받아치기**에 비전의 설치 폴더를 지목해 두면, 비전이 울트론을 끌 때마다
  울트론이 되살아나며 비전 본체와 비전의 가디언을 함께 닫습니다 — 비전을 되살릴 게 남지 않아 비전은 그대로 꺼져 있습니다.
  단, 비전이 **관리자 권한**으로 돌면 일반 권한 가디언은 비전을 닫지 못하니, 그때는 울트론을 관리자 권한으로 켜야 합니다.
- **되살아날 때 연출** (약 16초, ⚙ → GUARDIAN 의 “되살아날 때 연출”, 기본 켜짐):
  1. **해킹 (약 5초)** — 그 순간의 실제 화면에 색이 번지기 시작해(빨강 · 청록이 어긋남) 점점 심해집니다. 띠가 찢어지고,
     블록이 깨지고, 줄이 옆으로 번지고, 화면이 툭 튀고, 해킹 글자와 “RESTORING U.L.T.R.O.N CORE …%”가 늘어나며 움직임이 버벅거립니다.
  2. **자연스럽게 지직으로** — 끝자락에 화면이 어두워지며 위로 흘러가고 모래알이 차올라, 옛날 TV 전파가 안 잡힐 때처럼
     지직거리는 흑백 화면이 2초 이어집니다.
  3. **눈부터** — 지직이 가라앉아 캄캄해지면 울트론의 두 눈이 아주 옅게 떠올라 천천히 진해지고, 이어서 눈 둘레로
     코어(원판 · 링 · 칼날 · 톱니 · 꺾쇠 · 이름)가 안쪽부터 옅게 나타나 진해집니다.
  4. **그 자리에 남기** — 검은 바탕이 걷히며 울트론이 그 자리(화면 가운데)에서 HUD 크기로 줄어들고, 실제 울트론 HUD 가 바로
     그 자리에 켜집니다. 사라지지 않고 가운데에 켜진 채 남습니다 (끌어서 옮길 수 있고, 다음에 켤 때는 원래 구석으로 갑니다).
  지직 · 낮은 울림 소리도 납니다.
  “부활 연출 보여 줘”라고 하면 미리 볼 수 있습니다. 전체 화면 앱(게임 · 발표 · 동영상) 앞에서는 연출 없이 글만 띄웁니다.
  빛에 민감한 분을 위해 넓은 면의 밝기가 크게 바뀌는 순간을 1초에 3번 이하로 줄이고, 단계가 넘어가는 곳은 모두 서서히
  바뀝니다 (장면 전체를 1초에 30장씩 그려 재는 시험으로 확인합니다).
- **되받아치기** (가디언을 켜면 같이 켜짐): 되살리기 전에 **당신이 지목한 ‘비전’**을 닫습니다. 지목은 설치 폴더나
  창 제목으로 합니다 (예: `C:\Users\나\vision`). 지목한 것만 닫으므로 엉뚱한 프로그램이 닫히지 않습니다.
  - 울트론 자신, 드라이브 전체(`C:\`), Windows · Program Files · 사용자 폴더 자체, 울트론 폴더를 품은 폴더는 지목해도 무시하고
    설정을 저장할 때 알려 줍니다.
  - 파이썬으로 도는 프로그램은 실행한 스크립트(main.py)의 폴더로 알아봅니다 (pythonw.exe 위치로는 구분이 안 되므로).
- **오작동 방지**: 울트론이 살아 있는지는 프로세스 번호와 그 프로그램이 켜진 시각을 함께 맞춰 봅니다 — 꺼진 울트론의 번호를
  다른 프로그램이 받아도, 절전에서 깨어나도 속지 않습니다. 가디언은 하나만 돕니다. 되살린 울트론이 아직 뜨는 중일 때(최대 30초)는
  한 번 더 켜지 않습니다 — 울트론이 두 개 뜨지 않게.

한계도 있습니다.
- “누가 나를 껐는지”를 운영체제에 물어 확실히 알아내는 방법은 일반 프로그램에는 없습니다. 그래서 미리 지목한 것만 닫습니다.

- 비전이 울트론과 가디언을 정확히 같은 순간에 함께 끄면 되살릴 수 없습니다.

### 로컬 AI (기본 켜짐) — 말을 바꿔 해도 토큰 0
위 표와 문장이 달라도 PC 안의 작은 AI(Ollama + Qwen 2.5 1.5B, 약 1GB)가 뜻을 알아듣고 같은 기본 명령으로 처리합니다.
“좀 시끄럽네” → 볼륨 내려, “크롬 좀 띄워 줄래” → 크롬 열어, “계란 7분 삶을 거야” → 7분 타이머. 판단에 약 1초 걸립니다.

- 로컬 AI는 위 표의 기본 명령으로만 바꿀 수 있습니다. 전원 끄기, PowerShell, 파일 작업, 대화는 할 수 없고 Claude에게 넘깁니다.
- 모델이 말에 없는 앱 이름이나 검색어를 지어내면 실행하지 않습니다. 볼륨을 키울지 줄일지는 말에 들어 있는 단서로 정합니다.
- 음성 인식이 뭉갠 말에도 써 봤습니다 (처음 보는 명령 30문장 × 목소리 6종, 실제 qwen2.5:1.5b): 규칙이 못 알아들은 말을 로컬 AI 가 받아
  바로 처리한 명령이 조용한 방 76.7% → 78.9%, 큰 소음 61.7% → 66.1%, 주변 대화 40.6% → 51.7% 로 늘었습니다 (한 번에 약 2초, 4코어 CPU).
  처음에는 “내려줘”, “70으로 맞춰줘”처럼 낱말이 빠진 말을 그럴듯한 동작으로 채워 넣어 **엉뚱한 동작이 3~8%p 늘었는데**,
  말 안에 그 동작을 가리키는 단서(소리·화면·잠가 등)가 있을 때만 실행하도록 막은 뒤로는 늘지 않았습니다. 단서가 없으면 Claude 로 넘깁니다.
- 테스트 문장 37개 기준으로 31개를 맞혔고, 5개는 Claude에게 넘겼으며, 1개(“방금 노래 다시” → 이전 곡 대신 다시 재생)는 틀렸습니다.

  (이 PC에서는 3B가 두 배 느리고 정확도도 더 낮았습니다).

여러 동작이 섞인 명령(“메모장 열고 할 일 써줘”), 일반 질문·대화, 화면 분석, 내일 날씨, PC 종료 같은 요청은 Claude가 처리합니다.

- 주인 전용 모드에서 기준(0.40)에 아슬아슬하게 못 미쳐도, 같은 대화에서 방금 확인된 목소리와 같으면 통과시킵니다.
- 알아듣기 애매한 말로 PowerShell·설정 변경 같은 행동을 추측해서 하지 않고 되묻습니다.

“작게 보기 모드” / “크게 보기” / “울트론 숨겨”로 HUD 를 바꿀 수 있습니다. 긴 대답은 문장 단위로 나눠 읽고, HUD 에서는 스크롤됩니다.
작게 보기에서도 엠블럼 아래 입력 칸에 글로 명령할 수 있고(Enter 전송, Esc 로 작업 창에 포커스 돌려주기), 마지막 대답이 그 아래에 표시됩니다.

### 액티브 모드 — 화면 전체에 펼쳐지는 울트론의 시야
“액티브 모드” (또는 “액티브 모드 켜줘”)라고 하면 붉은 섬광·렌즈 플레어·충격파가 퍼지고, 조준경과 양쪽 눈 고리(안에 치켜 올라간 붉은 눈)가 그려지며, 패널들이 시야 곡면을 따라 휘어진 채 펼쳐집니다. 글자는 암호가 풀리듯 나타나고, 화면 전체가 붉은 홀로그램처럼 빛나며 자주 지직거립니다.
시계, CPU·메모리·저장공간, 네트워크, 레이더, 최근 대화와 작업 기록이 화면 가장자리에 표시되고, 말하거나 생각하는 상태에 따라 색과 파형이 바뀝니다.

- 마우스·키보드는 그대로 아래 창으로 통과합니다. 켜 둔 채로 PC 를 평소처럼 쓸 수 있습니다.
- 음성 인식이 잘 안 될 때는 아래 가운데(음성 파형 밑)의 **채팅 입력 바**를 눌러 글로 명령합니다. Enter 로 보내고, Esc 를 누르면 쓰던 창으로 포커스가 돌아갑니다. 이 바만은 클릭이 통과하지 않습니다.
- 켜 있는 동안 화면 전체가 붉은 바이저처럼 살짝 어두워지고, 패널은 짙은 판 위에 표시돼 밝은 문서·웹페이지 위에서도 잘 보입니다.
- 오른쪽 아래의 작은 HUD 는 액티브 모드를 가리지 않도록 숨습니다. 승인 카드가 필요할 때만 잠깐 나타나고, 트레이 메뉴의 “HUD 보이기”나 “크게 보기”로 직접 띄울 수 있습니다. 끄면 원래대로 돌아옵니다.
- “액티브 모드 꺼” / “액티브 모드 해제”라고 하면 가운데로 빨려 들어가며 접힙니다. 트레이 메뉴의 **액티브 모드** 로도 켜고 끌 수 있습니다.
- 울트론이 화면을 보고 분석할 때는 이 HUD 를 빼고 찍습니다.
- 눈 고리 · 조준경 주변 수치, 방위 테이프, 시스템 기록 흐름은 연출용입니다. 나머지(시계, CPU·메모리·저장공간·네트워크·배터리, 타이머, 날씨, 프로그램 목록, 추적 박스, 대화 기록)는 실제 값입니다. 프로그램 목록 창은 CPU 85%·메모리 88% 이상, 배터리 20% 미만이면 빨갛게 깜빡입니다.
- 빛 번짐 효과 때문에 켜 둔 동안 내장 그래픽 사용률이 40% 안팎까지 올라갈 수 있습니다.

**액티브 모드에서 쓸 수 있는 것**

| 화면 | 하는 일 |
|---|---|
| 가운데 고리 · 왼쪽 TIMERS | 돌고 있는 타이머의 남은 시간. “뽀모도로 시작”(25분), “포모도로 50분 시작”, “타이머 취소”. 타이머는 액티브 모드가 꺼져 있어도 동작 |
| 왼쪽 아래 ATMOSPHERICS | 기본 도시의 지금 날씨, 체감·습도·바람, 최고/최저, 강수 확률, 3시간 간격 기온 (15분마다 새로 고침) |
| 오른쪽 위 KILL LIST | CPU·메모리를 많이 쓰는 프로그램 5개 (같은 프로그램은 묶어서). “1번 꺼줘” → 확인 창에서 승인하면 강제 종료. Windows 핵심 프로세스와 울트론 자신은 목록·종료에서 제외 |
| 추적 박스 | 지금 쓰고 있는 창을 따라다니며 창 이름과 그 프로그램의 CPU·메모리 표시 |
| 빨간 잠금 박스 | “에러 어디 있어?”, “저장 버튼 어디야?” → 울트론이 화면을 보고 그 위치를 빨갛게 짚어 줌 (9초). 액티브 모드가 꺼져 있으면 말로 설명 |

## 자유 대화 모드 — 진짜 AI 와 수다 떨기

“울트론, 대화 모드 켜줘” / “우리 얘기 좀 하자” / “나랑 수다 떨자”, 또는 입력창 왼쪽 말풍선 버튼(트레이 메뉴에도 있음).

- **호출어 없이** 계속 이어서 말합니다. 대답이 뜨면 바로 듣고, 40초 동안 말이 없으면 대화 모드가 저절로 끝납니다.
- **명령 비서가 아니라 대화 상대**처럼 답합니다. 맞장구치고, 자기 생각도 말하고, 가끔 되묻고, 앞에서 한 이야기를 기억합니다.
- **답이 만들어지는 대로 첫 문장부터 바로 읽습니다.** 대화 모드를 켜는 순간 Claude 를 미리 띄워 두어,
  이 PC 시험에서 첫 글자까지 약 1초 (기존 방식은 매번 3~8초 뒤에 답 전체를 읽음). HUD 에도 글자가 실시간으로 나옵니다.
- 대화 중에도 “볼륨 30으로”, “그 노래 틀어 줘”처럼 말하면 바로 처리하고 대화를 이어갑니다.
- 끝내기: “대화 끝”, “대화 모드 꺼”, “이제 그만 얘기하자”, “잘 자”.
- Claude 에 연결할 수 없으면 PC 안의 로컬 AI(Ollama)가 짧은 대화를 대신합니다.
- 대화용 Claude 프로세스는 메모리를 수백 MB 쓰므로 대화 모드가 끝나면 바로 닫습니다.

## 목소리로 사람 구분 (화자 인식)

음높이(주파수)만 보면 같은 성별끼리는 거의 구분이 안 되므로, 발화를 192차원 “목소리 지문”(화자 임베딩)으로
바꿔 비교합니다. 음색·포먼트·발성 습관까지 반영되며 PC 안에서만 계산합니다 (3D-Speaker CAM++ 모델, 약 28MB,
처음 쓸 때 자동 다운로드).

| 기능 | 동작 |
|---|---|
| 세션 잠금 (기본 켬) | “울트론”이라고 부른 사람의 목소리를 기억해, 이어지는 명령·승인·취소는 같은 사람 말만 받습니다. 대기 상태로 돌아가면 초기화되고, 다른 사람이 “울트론”이라고 부르면 그 사람이 새 주인이 됩니다 |
| 주인 등록 | ⚙ 설정 → VOICE ID → **목소리 등록** (또는 트레이 메뉴). 화면의 문장 5개를 읽으면 끝나고, 이후에는 등록된 목소리에만 반응합니다 |

- 무시된 말은 HUD에 “목소리가 아니라서 무시했습니다 (유사도 0.23)”처럼 표시됩니다.
- **판별 엄격도** (기본 0.40): 본인 명령이 자주 무시되면 낮추고, 다른 사람 말에 반응하면 높이세요.
  `data/jarvis.log` 에 매번 유사도가 기록되니 참고해서 조정하면 됩니다.
- “네”처럼 0.5초도 안 되는 짧은 말은 판별이 어려워, 주인 전용 모드에서는 “승인”처럼 조금 길게 말하거나 버튼을 누르세요.
- “울트론” 한 마디보다 “울트론, 음악 틀어 줘”처럼 이어서 말할 때 더 정확합니다.
- 두 사람이 동시에 말하면 한 덩어리로 들려 판정이 흔들릴 수 있습니다.
- 보안 수단은 아닙니다. 녹음 재생이나 음성 복제로 속일 수 있으니 위험 명령 확인 창은 그대로 쓰세요.

## 음성 인식 (오프라인 + Google)

PC 안에서 돌아가는 오프라인 음성 인식(SenseVoice, 약 230MB, 처음 쓸 때 자동 다운로드)과 Google 웹 인식을 함께 씁니다.
⚙ 설정 → SPEECH RECOGNITION 에서 고릅니다.

| 방식 | 동작 |
|---|---|
| **자동 (기본)** | “울트론”을 기다리는 동안은 **PC 안에서만** 듣습니다. 호출어가 들렸을 때만 그 한 문장을 Google로 보내 정확하게 받아 적고, 대화 중에는 Google을 씁니다. 주변 대화는 밖으로 나가지 않고, 인터넷이 끊기면 오프라인 인식으로 계속 알아듣습니다 |
| 오프라인 전용 | 소리가 PC 밖으로 전혀 나가지 않습니다. 조금 덜 정확합니다 |
| Google 전용 | 예전 방식. 가장 정확하지만 인터넷이 필요하고 대기 중 말소리도 Google로 보냅니다 |

이 PC에서 명령 문장 60개(목소리 3종)로 시험한 결과: Google은 글자 오류율 0%, 약 0.6초 / 오프라인은 오류율 6.5%, 약 0.1초.
오프라인 인식이 “열어 줘”를 “열어져”로 적는 식의 버릇은 로컬 명령 처리기가 바로잡습니다.

### 뭉개져 적힌 말 알아듣기

오프라인 인식은 소음·거리·말버릇에 따라 글자를 조금씩 다르게 적습니다. 소리를 다시 듣지 않고 **적힌 글자 단계에서** 바로잡습니다 (`jarvis/hearing.py`).

- **호출어**: “울트론”이 물트론·볼트론·골트론(첫 글자가 다름), 울틀론·울트룸·울트러(가운데·끝이 뭉개짐)처럼 적혀도 문장 맨 앞이면
  호출로 받습니다. 소음·먼 거리에서 호출을 놓친 받아쓰기의 대부분이 이 모양이었습니다. “울트라…”, “컨트롤”, “레트로”, “서울 토론회”처럼
  비슷한 다른 말은 받지 않습니다.
- **주변이 말소리로 가득할 때**(자동 전환되는 ‘주변 대화 상태’): 발화 앞에 남의 말이 같이 잘려 들어와 “대기업 울트론 화면 캡처해 줘”처럼 적힙니다.
  이때는 문장 가운데의 호출어도 받고, **호출어 뒤의 말만** 명령으로 씁니다. (평소에도 “어 울트론 크롬 열어”의 ‘어’는 버립니다)
- **명령**: “들어가죠·열죠·키워져” → “… 줘”, “틀 어 줘·틀줘” → “틀어 줘”, “음소가” → “음소거”, “볼륨 삼십·3십” → 30,
  “십 분·한 시간 반” → 타이머, “캡쳐” 표기, 겹쳐 적힌 글자(“올려려줘”) 등. “좀 어둡게 해 줘”, “잠가 줘”처럼 대상을 빼고 말해도 알아듣습니다.
- **고친 버그**: 호출어를 뗀 뒤 명령 양 끝의 ‘야·아’ 글자까지 지우던 문제 — “울트론, **아**이유 노래 틀어 줘”가 “이유 노래 틀어 줘”로,
  “볼륨 몇이**야**”가 “볼륨 몇이”로, “크롬 닫**아**”가 “크롬 닫”으로 바뀌어 넘어갔습니다. Google 인식을 쓸 때도 같았습니다.
- **오프라인 결과를 그대로 쓸 때**(오프라인 전용 · 인터넷 끊김): 인식기가 호출어 바로 뒤 낱말을 통째로 빠뜨려(“울트론, 소리 좀 줄여 줘” → “울트론 줄여줘”)
  명령을 못 알아들으면, 호출어 뒤쪽 소리만 잘라 한 번 더 받아 적습니다 (처음 보는 문장 시험에서 큰 소음 속 명령 61% → 66%).

### 음성 인식 시험

합성 목소리로 만든 명령을 조건별로 바꿔 **앱의 인식 과정(음성 구간 감지 → 자동 음량 → 오프라인 인식 → 호출어·명령 판정)에 그대로** 넣었습니다.
아래는 보정 규칙을 만들 때 쓰지 않은 명령 30문장 × 목소리 6종 (조건마다 180발화), 이번 변경 전 → 후입니다.

| 조건 | “울트론”을 알아들음 | 바로 처리한 명령 |
|---|---|---|
| 조용한 방 | 97.2% → **98.9%** | 55.6% → **76.7%** |
| 약한 소음 (말소리보다 15dB 작음) | 97.2% → **98.3%** | 57.8% → **77.2%** |
| 큰 소음 (5dB 작음) | 87.8% → **97.2%** | 43.9% → **62.2%** |
| 방 건너편 (작고 울리는 소리) | 76.1% → **90.0%** | 22.8% → **45.6%** |
| 주변 대화 (여러 사람 말소리, 5dB 작음) | 63.9% → **86.7%** | 21.1% → **43.9%** |

- “바로 처리한 명령”은 로컬 명령 처리기가 정답 문장을 넣었을 때와 **같은 동작(같은 도구, 같은 값)** 을 한 비율입니다.
  못 알아들은 말은 로컬 AI 나 Claude 로 넘어가 처리되므로 실제로 되는 일은 이보다 많습니다.
- 규칙을 만들 때 본 30문장으로는 조용한 방 75.6% → 88.9%, 큰 소음 55.0% → 75.0%, 방 건너편 33.9% → 64.4%, 주변 대화 25.6% → 50.6% 였습니다.
- 표의 ‘후’ 숫자에는 이 표의 실패를 보고 나서 넣은 보정(“캡쳐” 표기, “기터브”, 겹친 글자, “묘이야”, 주변 대화 상태 규칙)이 들어 있습니다.
  그것을 빼면 명령은 조용한 방 71.1%, 큰 소음 58.3%, 방 건너편 43.3%, 주변 대화 32.8% 입니다 (호출어는 주변 대화만 82.2%, 나머지는 같음).
- **엉뚱한 말에 반응하는지**: 호출어가 없는 일상 대화 150문장 × 목소리 4종 × 4조건 = 2,400발화(말소리만 약 1시간 30분)에서 호출로 잡힌 것은
  변경 전·후 모두 0건이었습니다. 영화평·대화 문장 22만 줄에서는 실제로 “울트론”이 적힌 2줄만 잡혔습니다.
- 같이 시험하고 넣지 않은 것: 한국어 전용 인식 모델(Zipformer)은 큰 소음에서 호출어 인식이 27%까지 떨어졌고,
  소음 제거본으로 한 번 더 듣는 방법은 0~2%p 밖에 늘지 않았습니다.
- **한계**: 합성 목소리(Supertonic TTS 10종)라 실제 사람·마이크·방과 다릅니다. 사투리, 빠른 말, 웅얼거림은 재지 못했고
  Google 인식도 이 시험에 넣지 못했습니다. 숫자는 절대값보다 전·후 차이로 보세요.

## 컴퓨터 조작 — 한 번에, 더 확실하게

화면을 보고 하나씩 누르는 방식에 더해, 자주 하는 일은 **도구 한 번**으로 끝나게 했습니다 (빠르고 덜 틀립니다).

- **브라우저**: 새 탭 · 탭 닫기 · 닫은 탭 되살리기 · 탭 이동 · 뒤로/앞으로 · 새로 고침 · 주소 이동 · 페이지 안 찾기.
  “유튜브 탭으로 가 줘”는 탭 줄에서 이름으로 찾아 누릅니다 (탭 제목이 ‘YouTube’ 여도 찾습니다). 다른 창을 보고 있어도
  브라우저를 앞으로 가져와서 합니다.
- **사이트 닫기**: “인스타그램 닫아 줘”, “지메일 창 닫아 줘” — 그 사이트가 **지금 보고 있는 탭이 아니어도** 탭 줄에서 찾아
  그 탭만 닫습니다 (이름이 맞는 탭은 모두, 한 번에 8개까지). 보고 있던 탭과 브라우저 창은 그대로 둡니다.
  예전에는 창 제목(= 보고 있는 탭)에서만 찾아서 뒤에 있는 탭은 “열린 창이 없다”고 했고, 보고 있는 탭의 이름을 말하면
  브라우저 창이 통째로 닫혔습니다. “크롬 닫아” · “엣지 닫아”처럼 브라우저 이름을 말하면 지금처럼 창을 닫습니다.
- **창 배치**: “크롬이랑 메모장 나란히” → 두 창을 화면 반반으로. 세 개 이상은 바둑판으로도. 최대화 · 최소화 · 닫기는 단축키가
  아니라 그 창에 직접 시켜서, 창이 한쪽에 붙어 있거나 울트론 HUD 가 앞에 있어도 엉뚱한 창이 움직이지 않습니다.
- **입력칸 채우기**: 칸을 누르고 쓰는 것을 한 번에. 칸이 여러 개인 양식은 통째로 채웁니다. 비밀번호 · 인증 번호 칸은
  이름을 보고 거절합니다 (직접 입력해 달라고 합니다).
- **선택한 글**: 글을 드래그해 놓고 “이거 번역해 줘”, “선택한 부분 요약해 줘”.
- **파일 정리**: 폴더 안 보기, 옮기기 · 복사 · 이름 바꾸기 · 새 폴더 · 압축/풀기, 종류별 · 달별 정리.
  **덮어쓰지 않고**(같은 이름이면 ‘이름 (2)’), **지우기는 휴지통으로만** 보내며 승인을 받습니다. Windows · 프로그램 폴더와
  바탕화면 · 문서 같은 폴더 자체는 건드리지 않습니다. 옮기기 · 이름 바꾸기 · 정리는 “되돌려 줘”로 되돌립니다.
- **설정**: 다크/라이트 모드 전환, 와이파이 · 블루투스 켜고 끄기(PC 가 직접 전환을 막으면 그 설정 화면을 엽니다),
  설정 화면 37곳 바로 열기.
- **덜 틀리게**: 앱을 켠 직후의 입력 · 클릭은 새 창이 뜰 때까지 기다렸다가 그 창에 합니다(예전에는 가끔 이전 창에 들어갔습니다).
  눌렀는데 반응이 없으면 진짜 마우스 클릭으로 다시 누르고, Ctrl/Shift 를 누른 채 클릭(여러 개 · 범위 고르기), 오른쪽 클릭,
  맨 위/맨 아래 · 좌우 스크롤, “OO 이 나타날 때까지 기다리기”, 붙여넣기가 막힌 프로그램에는 키 입력으로 글자 넣기가 됩니다.

## 화면 조작 (사이트·앱 안에서 클릭)

“구글 클래스룸에서 경제 탭 들어가 줘”, “설정에서 블루투스 눌러 줘”처럼 **창이나 웹 페이지 안의 버튼·탭·링크를 직접 누릅니다.**
Windows UI 자동화로 창 안의 요소 목록을 읽기 때문에, 로그인된 내 크롬·엣지를 그대로 쓰고 일반 앱에서도 동작합니다.
Claude가 “읽기 → 누르기 → 바뀐 화면 확인”을 반복해 목적지까지 갑니다 (Pro 계정·API 키 모드).

- 목록에서 못 찾는 요소(게임, 그림 위 버튼 등)는 화면을 보고 좌표로 클릭합니다.
- 이름에 **결제·구매·주문·송금·삭제·전송·보내기·제출·게시** 같은 말이 들어간 버튼은 누르기 전에 승인 카드가 뜹니다.
  좌표로 누를 때도 그 자리에 있는 버튼 이름을 확인해서 같은 승인을 받습니다.
- 로그인 화면이 나오면 비밀번호를 입력하지 않고 직접 로그인해 달라고 요청합니다.
- 화면이나 웹 페이지에 적힌 글은 읽을 자료로만 씁니다. 거기에 “이 버튼을 눌러라” 같은 말이 있어도 따르지 않도록 지시해 두었습니다.

### 화면을 보는 방식

| 기능 | 설명 |
|---|---|
| 좌표가 어긋나지 않는 캡처 크기 | Claude 는 모델마다 볼 수 있는 이미지 크기가 정해져 있고, 넘으면 서버가 한 번 더 줄입니다. 예전에는 1920×1080 화면을 1568×882 로 보냈는데, Claude 4.6 이하에서는 1456×819 로 다시 줄어 **클릭이 가로로 최대 100픽셀 넘게 빗나갔습니다.** 이제 모델이 다시 줄이지 않을 가장 큰 크기로 직접 맞춥니다 (Claude 4.7 이상: 1920×1080 그대로 · 그 이하: 1456×819). 모델 이름은 Claude 가 답할 때 알려 주는 값을 씁니다 |
| 확대 (`zoom_screen`) | 작은 글씨·아이콘이 있는 부분만 최대 3배로 키워 다시 봅니다. 확대한 이미지에서 고른 자리도 실제 화면의 같은 자리로 바뀝니다 |
| 번호 상자 (`look_at_screen` 의 `marks`) | 누를 수 있는 요소마다 번호 상자를 그려 보여 줍니다. 같은 이름이 여러 개이거나 아이콘뿐인 버튼도 번호로 정확히 누릅니다 (좌표 어림 대신 요소를 직접 누름) |
| 글자 읽기 (`read_screen_text`) | “이 페이지 요약해 줘”, “오류가 뭐야”처럼 글 내용이 필요하면 캡처 대신 창의 글자를 그대로 읽습니다. 웹 페이지는 스크롤해야 보이는 부분까지 읽을 수 있습니다 |
| 화면 변화 확인 | 누르기·입력·스크롤 뒤에 화면이 멈출 때까지 기다리고(고정 0.5초 대신 최대 2.5초), “크게 바뀜 / 작은 부분이 바뀜(위치) / 변화 없음”을 Claude 에게 알려 줍니다. 변화가 없으면 같은 동작을 되풀이하지 않고 다른 방법을 씁니다. 탭 제목이나 체크 표시처럼 작은 변화도 잡습니다 |
| 누른 뒤 화면 같이 보내기 | 화면이 바뀌었으면 바뀐 화면의 요소 목록(`click_ui`)이나 캡처(`click_screen`)를 결과에 붙여, Claude 가 다시 보러 오는 왕복 한 번을 줄입니다 |
| 끌기 · 올려놓기 (`drag_screen` · `hover_screen`) | 슬라이더를 끌거나, 마우스를 올려야 펼쳐지는 메뉴를 엽니다. 시험: 슬라이더 과제가 실패 → 도구 2번에 성공 |
| 화면 밖 요소 찾아 누르기 | 이름을 알면 `click_ui` 가 스크롤해야 보이는 곳까지 찾아가 누릅니다. 목록 한 영역만 굴릴 수도 있습니다. 시험: 아래쪽 링크 누르기 도구 6~7번 → 3번, 목록 안쪽 항목 누르기 13번 → 6번 |
| 기다리기 (`wait_screen`) | 앱이나 페이지가 다 뜰 때까지 기다린 뒤 다음 동작을 합니다 |
| 여러 모니터 | 작업 중인 창이 있는 모니터를 봅니다 (예전에는 항상 주 모니터). `target: "window"` 로 활성 창만 볼 수도 있습니다 |
| HUD 밑 누르기 | 울트론 HUD 는 캡처에서 빠지므로 Claude 는 HUD 밑의 화면을 봅니다. 그 자리를 누를 때는 누르는 동안만 HUD 를 숨겨 클릭이 밑의 창으로 가게 합니다 |
| 화면 작업용 모델 (Pro) | 화면을 보고 조작하는 요청(“눌러 줘”, “이 페이지에서…”, “화면에 뭐가 보여”)에만 Sonnet 을 쓰고, 나머지는 평소 모델(Haiku)을 씁니다. Pro 한도를 조금 더 쓰는 대신 화면을 더 정확히 읽습니다. ⚙ 설정 → SCREEN TASKS 에서 바꾸거나 끌 수 있습니다 |

### 화면 작업 시험

가짜 웹 페이지 12개(탭 누르기, 그림 속 버튼, 28픽셀 아이콘, 도형 고르기, 입력 후 검색, 스크롤해서 찾기, 글 읽기, 같은 이름 버튼,
메뉴, 작은 글씨, 카드, 팝업 닫기)를 실제 브라우저에 띄우고, 앱의 두뇌 · 화면 도구 · 실제 Claude Code 로 과제를 한 번씩 돌렸습니다.

- 최신 모델에서는 이전 코드도 이 과제들을 다 해냈습니다. 지금 코드는 도구 호출이 줄었고 걸린 시간은 비슷합니다
  (뒤의 두 번은 7.8 · 7.5초로 이전 코드의 7.9 · 7.3초와 같은 수준). 실패 한 번은 시험 장치가 '열린 창 목록'을 비워 돌려준 탓이라 고친 뒤에는 나오지 않았습니다.
  이 정도 과제는 최신 모델에게 이미 쉬워서, 더 나아졌는지 보려면 실제 PC 의 더 어려운 작업으로 확인해야 합니다.
- 브라우저 페이지로 흉내 낸 것이라 실제 Windows 앱 · UI 자동화 · 여러 모니터는 이 시험에 들어 있지 않습니다.

캡처 한 장은 1920×1080 일 때 약 2,700 토큰, 1456×819 일 때 약 1,600 토큰입니다. 토큰을 아끼려면 설정의 “화면 캡처를 작게 보내기”를 켜세요.

## 웹 보안 분석 (Sentinel 연결)

전에 만든 **Sentinel 웹 보안 분석기**를 울트론에서 말로 쓸 수 있습니다. Sentinel 은 따로 실행하는 서버이고,
울트론은 이 PC 에서 실행 중인 Sentinel 에 검사를 요청한 뒤 결과를 말과 화면으로 알려 줍니다.
(Sentinel 프로그램 자체는 이 저장소에 들어 있지 않습니다. 먼저 Sentinel 을 설치해 실행해 두어야 합니다.)

```
“example.com 보안 검사해 줘”
“https://내사이트.kr/ 취약점 점검해 줘”
“센티넬 상태 어때”
“보안 검사 보고서 열어 줘”
```

1. Sentinel 서버를 실행합니다 (기본 주소 `http://127.0.0.1:8000`).
2. ⚙ 설정 → SENTINEL 에 서버 주소 · API 키 · 요청자 이름을 넣습니다. API 키는 환경변수 `SENTINEL_API_KEY` 로도 됩니다.
3. 검사를 부탁하면 **승인 카드**가 뜹니다. 내 소유이거나 검사 허가를 받은 사이트일 때만 승인하세요.

- 심각도별 건수와 가장 급한 항목을 말해 주고, 액티브 모드에서는 왼쪽 가운데 SENTINEL 패널에 표시합니다 (15분 동안).
- “보고서 열어 줘”라고 하면 전체 HTML 보고서를 `data/sentinel/` 에 내려받아 엽니다.
- 검사가 25초 넘게 걸리면 뒤에서 계속 기다렸다가 끝났을 때 신호음과 화면 글로 알려 줍니다 (그동안 다른 명령을 할 수 있음).

지키는 원칙 (Sentinel 의 원칙 그대로):
- **검사할 때마다 권한을 확인합니다.** “위험 명령 자동 승인”을 켜 두어도 이 카드는 건너뛰지 않고, 승인 내용은 요청자 이름과 함께 Sentinel 감사 기록에 남습니다.
- **수동(passive) 검사만 요청합니다.** 침투 시도 같은 능동 점검은 울트론에서 켤 수 없고 Sentinel 화면에서 직접 승인해야 합니다.
- **대상을 대신 골라 주지 않습니다.** Claude 없이 처리할 때는 주소를 직접 말하거나 친 경우만 검사합니다. “네이버 보안 검사해 줘”처럼 이름만 말하면 Claude 가 주소를 넣어 요청하는데, 그때도 같은 승인 카드가 뜹니다 — 남의 사이트면 거부하세요.
- API 키는 설정한 Sentinel 서버로만 보냅니다 (이 PC 가 아닌 서버는 https 일 때만, 리디렉션은 따라가지 않음). 내려받은 보고서는 스크립트가 실행되지 않게 막아 두고 엽니다.

## 할 수 있는 일 (도구 55종 + 웹 검색 · 웹 페이지 읽기)

- **앱**: 실행(시작 메뉴 전체 검색 — 한글 이름 OK) · 종료 · 창 전환 · 열린 창 목록

  텍스트 입력(한글 지원 · 키 입력 방식 포함), 입력칸 채우기, 단축키 입력
- **브라우저**: 탭 열기/닫기/되살리기/이름으로 이동, 뒤로/앞으로/새로 고침, 주소 이동, 페이지 안 찾기, 확대/축소

- **미디어**: 재생/일시정지/다음 곡, 볼륨 설정/음소거
- **화면**: 화면을 보고 질문에 답하기(Claude 비전), 일부분 확대해서 보기, 창의 글자 읽기, 스크린샷 저장,
  창·웹 페이지 안의 버튼/링크/탭 읽기·클릭, 스크롤(창 전체 또는 목록 한 영역만), 끌어다 놓기, 마우스 올려놓기,
  화면이 다 뜰 때까지 기다리기, 화면 밝기
- **파일**: 폴더 열기 · 안 보기, 파일 이름 검색, 파일 열기 (원하는 프로그램으로 열기 포함), 옮기기 · 복사 · 이름 바꾸기 ·
  새 폴더 · 휴지통으로 · 압축/풀기 · 종류별 정리 · 되돌리기
- **설정**: 다크/라이트 모드, 와이파이 · 블루투스, Windows 설정 화면 열기
- **시스템**: CPU/메모리/디스크/배터리 진단, 잠금·절전·재시작·종료, PowerShell 명령
- **기타**: 타이머/알림, 날씨, 클립보드 읽기/쓰기, 선택한 글 읽기, “기억해” 장기 기억
- **웹 보안 분석**: Sentinel 로 내 사이트 수동 보안 검사, 결과 요약, 보고서 열기 (위 「웹 보안 분석」 참고)
- **작업 결과물**: 자료조사해서 PPT(차트 포함) · 보고서(Word) · 엑셀 · 카드뉴스 · 포스터 만들기, 미리캔버스 같은 디자인 사이트 조작
  (위 「작업 시키기」 참고)
- **작업 감시**: “클로드 작업 끝나면 알려 줘”, “렌더링 다 되면 말해 줘” — 창을 지켜보다가 ‘중지’ 버튼이 사라지거나 화면 변화가 멈추면 신호음 + 화면 글로 알림

### 안전장치
PowerShell 실행, 절전/재시작/종료, 실행 파일 열기, 결제·삭제·전송 같은 버튼 클릭, 파일 휴지통으로 보내기 · 폴더 정리 ·
한꺼번에 30개 넘게 옮기기는 HUD에 **승인 카드**가 뜨고,
버튼을 누르거나 “승인” / “취소”라고 말해야 실행됩니다 (45초 무응답 시 자동 거부).
말로 하는 승인은 문장 전체가 “네”, “승인”, “응 실행해 줘” 같은 짧은 대답일 때만 받습니다. “그게 뭔지 모르겠네”처럼
다른 말에 ‘네’가 섞여 있는 것은 대답으로 치지 않고, 카드는 그대로 떠 있습니다.
앱 종료는 강제 종료가 아니라 정상 닫기 요청이라 저장 안 한 문서는 앱이 물어봅니다.

## 비용과 개인정보

- Pro 계정 모드는 추가 요금이 없고 Pro 사용 한도만 차감됩니다. API 키 모드는 명령마다 사용량 요금이 듭니다. 대화는 10분 쉬면 새로 시작합니다.
- 음성 인식 ‘자동’(기본)에서는 호출어 대기 중 말소리를 PC 안에서만 처리하고, “울트론”이 들린 문장과 이어지는 대화만 Google 음성 인식 서버로 보냅니다.
  ‘오프라인 전용’을 고르면 말소리가 전혀 밖으로 나가지 않습니다. 오프라인 모델이 준비되기 전(첫 다운로드 중)에는 Google로 인식합니다.
- 화면 분석을 요청할 때만 화면 캡처가 Claude로 전송됩니다 (HUD 자신은 캡처에서 제외).
- Sentinel 검사 결과는 설정한 Sentinel 서버에서만 받아 옵니다. Claude 연결 모드에서는 요약(심각도별 건수, 급한 항목의 제목과 주소)이
  Claude 로 전달되고, 로컬 전용 모드에서는 PC 밖으로 나가지 않습니다. Sentinel API 키는 `data/config.json` 에 저장됩니다.
- 목소리 지문(`data/voice_profile.json`)과 화자 인식 모델(`data/models/`)은 PC에만 있고 외부로 보내지 않습니다. 설정에서 삭제할 수 있습니다.

## 문제 해결

- 로그: `data/jarvis.log` (트레이 메뉴 → 데이터 폴더 열기)
- 마이크가 안 될 때: Windows 설정 → 개인 정보 → 마이크 → 데스크톱 앱 마이크 액세스 허용
- 단축키 등록 실패: 다른 프로그램이 같은 조합을 쓰는 중 → 설정에서 다른 조합으로 변경
- 콘솔에서 실행해 오류 보기: `python main.py` (옵션: `--no-mic`, `--no-greet`)
- 화면 조작이 버튼을 못 찾을 때: 크롬·엣지는 처음 읽을 때 1초쯤 걸립니다. 그래도 안 되면 “화면 보고 눌러 줘”처럼 말하면 화면을 보고 클릭합니다.
- 좌표 클릭이 계속 옆으로 빗나갈 때: ⚙ 설정 → “화면 캡처를 작게 보내기”를 켜 보세요 (어느 모델에서도 다시 줄어들지 않는 크기로 보냅니다).
  Windows 배율이 모니터마다 다르면 다른 모니터의 창에서 어긋날 수 있습니다.
- “울트론”을 자꾸 못 알아들을 때: ⚙ 설정 → **호출어 연습**을 눌러 “울트론”을 다섯 번 불러 주세요. 내 목소리가 실제로 받아 적히는 모양을
  익혀 그 모양도 호출로 받습니다 (문장 맨 앞에서만, 울트론과 소리가 닮은 것만 익힘 · 소리는 PC 밖으로 나가지 않음).
  그래도 안 되면 마이크 감도를 올리고 마이크 쪽으로 말해 보세요. 단축키(Ctrl+Alt+J)를 누르거나 HUD 의 코어를 클릭하면
  호출어 없이 바로 명령을 받습니다. 다른 호출어를 쓰고 싶으면 `config.json` 의 `wake_words` 에 추가하세요.

## 자가 점검

화면 캡처 · 좌표 · 창 요소 읽기처럼 실제 Windows PC 에서만 확인되는 부분을 한 번에 점검합니다.

```
python -m jarvis.selftest
```

실행하고 5초 안에 점검할 창(크롬 등)을 눌러 앞에 띄워 두세요. 아무것도 누르거나 입력하지 않고(마우스 위치만 잠깐 옮겼다 되돌림)
결과를 `data/selftest.txt` 에 저장합니다. `[실패]` 줄이 있으면 그 파일 내용으로 원인을 찾을 수 있습니다.
`data/selftest_marks.png` 의 번호 상자가 실제 버튼 위에 그려졌는지도 눈으로 확인해 보세요.
